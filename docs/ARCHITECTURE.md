# 生产架构与实施路线

## 设计边界

研究、数据和交易必须解耦。研究服务可以产生目标仓位，但不能直接拥有券商密钥；执行服务只能接收通过风控的订单意图。AI 可以解读材料和提出假设，但不得直接下单，也不得把未经验证的文本结论写成交易信号。

```text
交易所/数据商 -> 采集 -> 原始数据湖 -> 标准化/复权 -> Point-in-time 数据库
                                              |
                         基本面/因子/期权面/事件特征
                                              |
                              研究 API -> 回测 -> 组合与风控
                                              |
                                  人工批准 -> 执行网关 -> 券商

公告/财报/新闻 -> 文档解析 -> 来源与时间戳 -> AI 解读 -> 研究记录（不直连执行）
```

## 推荐技术栈

| 层 | 第一阶段 | 生产阶段 |
|---|---|---|
| 计算 | Python 标准库/Polars 或 pandas | Polars + NumPy/Numba，批量任务用 Ray 可选 |
| API | FastAPI | FastAPI + 独立研究/风控/执行服务 |
| 时序与财务数据 | Parquet + DuckDB | PostgreSQL/TimescaleDB + 对象存储 |
| 调度 | cron/手工任务 | Dagster 或 Prefect |
| 缓存/队列 | 无 | Redis + NATS/Kafka（按规模选择） |
| UI | API/Notebook | Next.js 研究台与可审计报告页 |
| 可观测性 | 日志 | OpenTelemetry + Prometheus/Grafana |

## 数据源建议

- 美股行情与公司行动：选择带 SLA、复权说明和 point-in-time 能力的数据商；免费源只用于原型。
- A 股：行情、停复牌、ST 状态、涨跌停板、财务公告日期、前复权/后复权因子必须分表保存。
- 期权：需要完整合约主数据、bid/ask、成交量、持仓量、隐波曲面、利率和分红假设。
- 加密：按交易所保存 spot/index/mark 三种价格，记录资金费率、合约面值、保证金阶梯和强平规则。
- 新闻与公告：保存原文、URL、抓取时间、发布时间、语言、证券映射和内容哈希。

数据供应商接口放在 `data/` 下，通过协议隔离。不要让策略直接调用供应商 SDK；先落原始数据，再标准化。这样数据修订时能重放，也能防止回测混入未来数据。

## 必须补齐的生产能力

1. **Point-in-time 数据库**：财报必须按首次披露时间可见，修订值另存版本；处理退市证券以避免幸存者偏差。
2. **公司行动**：拆并股、分红、配股、增发、代码变更、合约换月及复权一致性测试。
3. **日历与微观结构**：独立交易所日历、半日市、休市、集合竞价、停牌、ST/科创板/创业板不同涨跌幅。
4. **组合层**：多币种现金账本、汇率、融资利率、借券、保证金、期权组合 Greeks、压力测试、VaR/CVaR。
5. **验证层**：walk-forward、purged cross-validation、参数稳定性、容量、冲击成本和基准归因。
6. **安全与审计**：密钥托管、最小权限、订单限额、双人审批、kill switch、不可变审计日志。
7. **AI 评估**：固定金标集评估财报数字抽取、引用正确率、情绪方向和拒答；提示词与模型升级必须回归测试。

## 推荐里程碑

### M1：研究闭环（当前底座向前扩展）

- 接入一个美股和一个 A 股合规数据源
- DuckDB/Parquet point-in-time schema
- 因子计算、策略注册、回测报告和 Notebook 示例
- 财报/公告材料入库以及带来源的 AI 研究报告

验收：固定数据快照能完全复现实验；同一策略多次运行结果一致；不存在当日收盘信号在当日成交。

### M2：多资产组合

- 期权链、波动率曲面、Greeks 聚合与情景分析
- 加密永续资金费率和跨所基差策略
- 多币种组合会计、风险预算和组合优化

验收：逐笔现金账与独立手算样本一致；极端价格和缺失行情有确定处理策略。

### M3：模拟盘与受控实盘

- 券商适配器、订单状态机、幂等、断线恢复
- pre-trade/post-trade 风控和人工批准
- 监控、告警、审计与灾备演练

验收：先 paper trading；故障注入、重复回报、部分成交和断线场景全部通过后，再以极小额度灰度。

## AI 输出使用原则

AI 适合做材料归纳、矛盾点发现、情景树和待验证假设，不适合被当作事实数据库或确定性收益预测器。最终信号应来自可复现的数据特征；AI 结论只能作为带置信度和失效期限的研究特征，并且必须保留原始证据供人工复核。

# 回测审计

目的：在结论出门前找出会让它失效的问题。本项目回测目前的已知状况是：用当前成分股回看历史（幸存者偏差）、未加完整成本、未处理停牌/涨跌停、无 PIT 基本面、区间 2023-08 起约三年。任何报告都要把这些说清楚，而不是只报数字。

## 审计清单

按顺序过一遍，每项标 ✅ / ⚠️ / ❌ / N/A，并写一句证据（代码位置或参数值）。

### A. 数据
- A1 股票池是否 point-in-time（历史成分/退市股是否包含）
- A2 价格是否原始价 + 复权因子（而非可回溯变化的复权价）
- A3 基本面/事件是否按 `accepted_at` / `published_at` 截断
- A4 多币种是否用当日汇率折算；ADR 是否单独处理
- A5 是否有数据缺口（停牌、缺日）被静默填充

### B. 时点
- B1 信号计算用到哪一根 bar 的收盘；成交在下一根 bar 的什么价（open / VWAP / close）
- B2 盘后发布的信息（财报、公告）是否只能在下一开盘生效
- B3 再平衡频率与信号频率是否一致（月频信号不能周频成交）
- B4 交易日历是否正确（NYSE 半日、A 股节假日）

### C. 成本与约束
- C1 佣金、A 股印花税（卖出单边）、过户费；美股 SEC fee
- C2 滑点模型（固定 bp 或 Almgren–Chriss），参数来源
- C3 涨停不可买、跌停不可卖、停牌冻结、100 股整数、T+1
- C4 换手定义（建议单边 Σ|Δw|/2）及年化换手；成本对收益的敏感度（成本 ×0.5 / ×2）
- C5 容量：按 ADV 的 1% 估算策略能承载的资金规模

### D. 统计
- D1 基准与超额：SPY / 000300 / 池内等权；α、β、信息比率
- D2 区间是否覆盖至少一个完整下行周期；子区间（逐年）表现
- D3 Sharpe 置信区间（bootstrap，现有引擎已有）
- D4 多策略/多参数比较是否做了 Deflated Sharpe 或 PBO
- D5 walk-forward / CPCV 的样本外结果与样本内差距
- D6 扰动测试：信号延后 1 天、去掉贡献最大的 10 只、参数 ±20%

### E. 泄漏
- E1 因子或标签是否用了未来数据（滚动窗口右端、行业分类时间戳）
- E2 LLM 参与的信号：评估样本是否在模型知识截止日之后；历史样本是否脱敏
- E3 参数是否在同一区间上选出来又在同一区间上报告

### F. 表述
- F1 报告标题是否标注"描述性回测 / 样本外验证 / 可交易候选"三档之一
- F2 候选标的是否写成"候选池"而非买入指令（红线 1）
- F3 是否列出了本次未处理的项目（而不是只写做了什么）

## 报告模板

```
# <策略名> 回测审计 <日期>
状态: 描述性回测 | 样本外验证 | 可交易候选
## 结果摘要（含基准）
| 指标 | 策略 | 基准 | 超额 |
## 审计表
| 项 | 状态 | 证据 |
## 必须修复后才能升级状态的问题
## 敏感度（成本 ×0.5/×1/×2；信号延后 1 天；去掉 top10）
## 未处理事项
```

## 判定规则

- A1–A3、B1–B2 任一 ❌ → 只能标"描述性回测"，且报告首段必须说明。
- C1–C3 未做 → 不得给出年化收益的两位小数精度，改为区间表述。
- D1 缺失 → 拒绝下结论，先补基准。
- 状态升级必须有对应的代码或数据变更，不能靠文字说明。

## 与项目的对应

- 回测代码：`src/quant_workbench/backtest/`；策略：`strategy/`；报告：`reports/`。
- 现有报告 `STRATEGY_RESEARCH_2026-09-13.md` 属于"描述性回测"，缺 D1、C1–C3、A1。
- 更新报告时保留原报告，另存新日期文件，并在新文件里写"相对上一版修复了什么"。
